# biss-brain — Design Context

## Users

A single technical power-user (Bissbert) curating a local RAG memory across many
projects. The brain inspector is consulted *between* coding sessions — late at
night, after a long day, when the user opens it to reconcile what the brain
captured against what they actually remember. They are not novices. They will
never see an onboarding tour. They want signal, not chrome.

## Brand Personality

Three words: **direct, simple, efficient.**

Not "minimal" — minimalism is a defaults-aesthetic that hides behind whitespace.
Direct means the answer is on screen as soon as the page loads, with the
strongest data shown most prominently. Simple means one type ramp, one accent,
no ornament. Efficient means tabular density: many rows, fast scan, no
prettifying that costs information.

## Aesthetic Direction

**Lab notebook at night.**

The reference object is a hardback ruled lab journal sitting open on a desk in
a darkened room — graph-paper grid faintly visible, page numbers in the gutter,
column headings in small caps, hand-tabulated entries. Translated to web:

- Deep gunmetal page (`#0e0e16`), not pure black. Faint 16px graph grid behind
  every page (`rgba(148,163,184,0.035)`) — present but never decorative.
- Hairline rules (1px) instead of cards. Rule lines and whitespace separate
  sections; nothing is wrapped in a rounded box with a shadow.
- One accent — biss-design-system purple `#9333ea` — used only for the active
  state and focus ring. Teal `#2dd4bf` is reserved for live counters and pin
  state. Coral `#f43f5e` is reserved for destructive actions.
- Small-caps section labels (`letter-spacing: 0.12em`, neutral-500) for the
  marginalia / column headings.
- Tabular numerics (`font-feature-settings: 'tnum'`) for every count, hash,
  timestamp, score.

### Anti-references (what to actively avoid)

The current build of this very UI: dark dashboard with purple `#7c6af0` accent,
system-ui font, rounded cards in a flex grid. That's the AI-slop fingerprint
this redesign exists to repudiate. Specifically: no glow effects, no
glassmorphism, no `border-left:` accent stripes, no gradient text, no
purple-to-teal gradient backgrounds (despite the design system defining one),
no glow shadows on hover.

### Theme

Dark, derived from viewing context (late-night curation in a dim room).
Lab-notebook reading discipline applied: text is `#e2e8f0` (soft white from the
design system) on `#0e0e16`, line-height +0.05 over the bright-bg default to
compensate for perceived weight loss on dark.

## Typography

The biss-design-system specifies Inter + DM Sans + JetBrains Mono. Inter and
DM Sans are reflex-default fonts and do not match the "direct, simple,
efficient" voice — they are pleasant but generic. The design-system tokens for
*colour, spacing, and shadows* are kept; the typography is the one place this
project departs.

- **Display / headings**: **Schibsted Grotesk** 600/700 — news-editorial
  geometric sans, cleanly cut, slightly more direct than humanist body faces.
- **Body**: **Hanken Grotesk** 400/500 — efficient humanist body, excellent at
  small sizes for tabular content.
- **Mono / data**: **JetBrains Mono** 400 — kept from the design system, but
  used purposefully for hashes, timestamps, and chunk IDs (the "data column"),
  never as decoration.

Type ramp (modular 1.25, fixed `rem` for app UI per impeccable rules):
- 0.75rem — small caps labels
- 0.875rem — body small / metadata
- 1rem — body
- 1.25rem — section heading
- 1.5625rem — page heading
- 1.95rem — display / brand mark

## Design Principles

1. **Every pixel is data or whitespace.** No ornament. No mood lighting. If a
   pixel doesn't carry information or open up a row of information, it leaves.

2. **Density over comfort, on a wide-set ruler.** Lab notebooks pack rows
   tightly because the reader is scanning, not reading prose. Body 0.875rem,
   row height ~32px, hairline rules between rows. Generous outer margin so the
   grid has air around it; tight inner gutters so rows scan fast.

3. **The hash is the truth, the label is convenience.** Project hashes,
   chunk IDs, vector distances, timestamps — all set in JetBrains Mono with
   tabular numerics. Human labels (project paths, kinds) sit in Hanken
   Grotesk. The two type voices encode "machine truth vs. human gloss" without
   saying so.

4. **One accent, sparingly.** Purple `#9333ea` appears only on (a) the brand
   mark, (b) the active nav route's underline, (c) the active project row's
   left edge, (d) focus rings. If purple is showing up anywhere else, that's
   over-decoration and it goes.

5. **Asymmetric, not centred.** The page is a left-aligned spread with a
   marginalia gutter on the left for metadata (small caps, counts, last-active
   timestamps) and the main content on the right. Centring is the safe
   reflex; the lab notebook never centres anything.
