# biss-brain v0.7 — Analysis and Phased Upgrade Plan

Status: **APPROVED 2026-10-25** (decisions recorded in §6). Branch: `upgrade/v0.7` (local only, never pushed).
Baseline: master @ `1b07bee` + uncommitted plugin.json (0.6.2, repository URL), 299 tests green.
Date: 2026-10-25.

---

## 0. TL;DR

The brain-inspired architecture is sound on paper, but the data shows that **none of it has
ever run on real usage**. 94 % of the stored corpus is raw transcript truncated at 2,000 chars
(0.5.4's silent passthrough fallback). `retrieval_count` is 0 on every chunk. There are no arcs,
no supersessions, no reconsolidations and almost no backlinks. The nightly dream pass fails every
night on a bare `claude` subprocess call. The retrieval path discards relevance order and re-sorts
by decay alone.

So v0.7 is ordered as follows:

1. **Measure first.** Build an eval harness (synthetic plus real) and get a baseline before touching
   anything.
2. **Fix correctness.** Ranking, prompt rendering, the CLI resolver, SQL binding and the open SEC
   items. Then re-measure.
3. **Add the missing tiers.** Provenance and trust, temporal validity, core memory, and gated
   proactive injection.
4. **Make capture cheap and robust.** Batch distillation, no 120 s blocking PreCompact, defer
   instead of truncate when the CLI or Ollama is down, scoped hooks.
5. **Make every brain mechanism earn its place.** Run ablations with replay. Keep what helps or is
   neutral and cheap, and turn off (not delete) the rest.
6. **Package.** Migrations with backup, doctor, docs, 0.7.0.

Several steps change or rewrite existing user data. They are listed as **decisions for you** in §6.

## 2. Code analysis — defects and debts

Severity: **H** breaks a core promise, **M** wrong or risky behaviour, **L** hygiene.

### 2.1 Retrieval quality
| # | Sev | Where | Problem |
|---|---|---|---|
| R1 | H | `scripts/recall.py:503`, `mcp/server.py:271` | Results are re-sorted **by decay_score alone**, which throws away the BM25/vector/RRF (and reranker) order. Fresh irrelevant chunks outrank old exact hits. This kills MRR. |
| R2 | M | recall/MCP | Fetches only `top_k` (×4 only with rerank), so there is no candidate pool for fusion with recency, trust or validity. |
| R3 | M | `common.hybrid_search` | Hybrid falls back to dense silently; FTS index freshness is never checked after inserts. |
| R4 | M | recall, MCP, inject_context | STDP, RIF, labile-window and count-bump helpers are **triplicated** and have drifted. One `retrieval.py` pipeline is needed. |
| R5 | M | `_recall_global` | Cosine gate 0.85 with no hypothesis filter (**SEC-004 still open**). |
| R6 | L | `backlinks._L2_GATE = 0.78` | Assumes unit-norm vectors; nomic vectors from Ollama aren't guaranteed normalised. |

## 3. State of the art (verified 2026-10-25; sources in Appendix A)

| System | Capture | Store / search | Injection | Notable |
|---|---|---|---|---|
| **Claude Code auto memory** | Claude writes files itself | `~/.claude/projects/<p>/memory/MEMORY.md` (index) + topic files | first 200 lines / 25 KB of MEMORY.md each session | Shared across worktrees; not in subagents; plain files. |
| **claude-mem** | 6 hooks; LLM compresses tool observations | SQLite FTS5 + Chroma hybrid | progressive disclosure (index ~50–100 tok/hit → full obs) | web viewer, `<private>` tags |
| **Mem0** | LLM extraction ADD/UPDATE/DELETE/NOOP (paper); newer: ADD-only + time-aware retrieval | vector + BM25 + entity, fused | ~1.8K tok/query (paper) | LoCoMo J 66.9 (paper); p95 1.44 s |
| **agentmemory** | 12 hooks incl. PreCompact, PostToolUseFailure; SHA-256 dedup | BM25 + vector + graph, RRF k=60 | SessionStart budget 2,000 tok; auto-inject opt-in | decay + supersession with history; publishes an eval (LongMemEval-S R@5 95.2) |
| **memsearch** | Stop hook → Haiku bullets → daily markdown | markdown = source of truth; Milvus as rebuildable index | 3-layer recall (chunk → section → transcript) | bge-m3 ONNX |
| **Zep/Graphiti** | LLM fact extraction | temporal KG; bi-temporal edges `t_valid/t_invalid` + `created/expired` | ~1.6K tok | contradicted facts invalidated, never deleted |
| **Letta** | agent edits its own blocks | core memory blocks with char `limit` | always in context | sleep-time compute |

Hook facts that constrain the design:
- `additionalContext` caps at **10,000 chars**. Past that, Claude gets a file path plus a 2,000-char preview. Command-style text can trip prompt-injection defences, so phrase injected content as facts.
- `UserPromptSubmit` default timeout is 30 s; we set 5 s. A timed-out hook's output is discarded.
- `SessionEnd` gets 1.5 s by default (≤ 60 s configurable).
- `Stop` receives `last_assistant_message`.
- `${CLAUDE_PLUGIN_ROOT}` resolves in hooks and in .mcp.json. It changes on update, so no state goes there.
- `${CLAUDE_PLUGIN_DATA}` is deleted on uninstall, so the brain stays at `~/.claude/brain`, which is precious.

Evidence on brain mechanisms is **thin**:
- HeLa-Mem: removing forgetting had little effect on LoCoMo.
- No paper cleanly isolates retrieval-triggered reconsolidation.
- VibeMemBench (arXiv 2609.23570): 11 of 12 existing memory-system/solver pairings **did not beat memory-off** on coding tasks.

So measured wins are the differentiator, not mechanism count.

**Where biss-brain can go beyond the field:**
1. **Provenance-derived trust with taint propagation.** None of the Claude Code competitors has this.
2. **Bi-temporal validity in a local plugin.** Only Zep does this, and it is server-side.
3. A **published, reproducible ablation** for every brain mechanism.
4. **Core memory that complements auto memory** instead of duplicating it.
5. Sleep-time consolidation that actually runs and is cheap.

## 4. Design targets for v0.7 (numbers come from the baseline; these are initial gates)

| Target | Gate |
|---|---|
| Recall@5 on real suite | ≥ baseline + 15 pts after Phase 1 (decay-sort fix alone should move MRR) |
| Mechanism inclusion | Keep if ΔMRR ≥ +0.01 (bootstrap 95 % CI excludes 0), or ΔMRR within ±0.01 at ≤ 5 ms/query and no LLM cost; else default-off |
| UserPromptSubmit hook | p95 ≤ 800 ms warm, hard internal deadline 2.5 s, never blocks on LLM |
| Injection budget | ≤ 1,500 tokens (~6,000 chars) UserPromptSubmit; ≤ 2,000 SessionStart; never near 10,000-char cap |
| Injection precision | ≥ 0.7 on suite (fraction of injected items judged relevant); abstain on ≥ 80 % of off-topic prompts |
| Distill cost | ≤ 1 CLI call per session segment (session end / compact / idle), not per Stop |
| PreCompact | returns in ≤ 2 s (capture only); distill async |
| Hook no-op cost | excluded dirs exit in shell before Python (≤ 20 ms) |

## 5. Phased plan

Each phase ends with: tests green, new tests for new behaviour, eval re-run (where relevant), a
short entry in `docs/plans/v0.7-progress.md`, and **a commit only after you approve it**.

### Phase 0 — Safety rails and eval harness (no behaviour change)
- `scripts/brain_snapshot.py`: copy `~/.claude/brain` (or selected projects) into a scratch dir; all
  eval runs use `BISS_BRAIN_ROOT=<snapshot>`. **Guard: the harness refuses to run when the root
  resolves to the real `~/.claude/brain`.**
- `scripts/eval/` (`python -m scripts.eval run …`, one command, also `/biss-brain:eval`):
  - suites:
    - **synthetic** (committed, `tests/fixtures/eval/`): ~200 memories across 3 fake projects,
      ~80 questions covering single-fact, multi-session, knowledge-update (supersession), temporal
      ("what was true on date X"), cross-project distractors, poisoning items (web/tool-derived
      imperatives), and off-topic prompts (abstention).
    - **real** (**never committed**; lives at `~/.claude/brain-eval/questions.jsonl`, outside the
      brain root so snapshots and migrations never see it): 30+
      questions over the projects you approve (§6 D1). Questions are paraphrased, not lifted from
      the gold chunk, so BM25 isn't inflated. Gold = chunk ids (multi-gold allowed).
  - metrics: recall@{1,3,5,10}, MRR, nDCG@10, per-category breakdowns; injection precision and
    abstention rate for the UserPromptSubmit path; latency p50/p95; bootstrap CIs.
  - ablation matrix: `--ablate stdp,rif,reconsolidation,decay,dmn,dream,backlinks,rerank,hybrid`
    toggles via config overrides; **replay mode** runs a train split of queries/sessions first so
    stateful mechanisms have state, then scores the held-out split. Reports `never_exercised`
    explicitly.
  - output: JSON + markdown table in `docs/eval/` (synthetic results only; real-suite results are
    aggregate numbers only, no content).
- Hygiene: `.gitignore` `.claude/worktrees/`, untrack `tests/__pycache__`.
- **Deliverable:** baseline numbers for current code on both suites.

#### Phase 0 results (2026-10-25)

Built: `scripts/brain_snapshot.py`, `scripts/eval/{run_eval,eval_metrics}.py`, `scripts/retrieve.py`
(pure retrieval shared by recall, MCP and inject; parity-tested against v0.6.2 goldens), synthetic
suite (45 memories, 21 answerable + 8 no-answer), real suite (37 answerable + 12 no-answer over the 7
plugin projects, 222 chunks; snapshot only). Grading is by answer term groups reduced to key tokens
(numbers, names), with gold ids as a secondary key. Term groups are more robust to re-distillation
than ids, but not immune: each run prints a corpus-coverage count (answerable questions with at
least one live answer row), so answers lost by re-distillation show apart from lost ranking.

Real suite, k=5, coverage 37/37. Three table states, so the fixes can be attributed separately:
`stored` = tables as they are today (stale vectors, no FTS index); `+FTS` = same rows and vectors
with an FTS index built; `re-embedded` = rows re-embedded with the named model into fresh tables
with an FTS index.

Reading the table: the FTS index alone recovers most of the recall (hit@5 0.32 → 0.84, a Phase 1
fix). Fresh vectors plus dropping the decay re-sort fix the ordering (MRR 0.48 → 0.70). A better
model adds about 0.16 more. The three effects are separate, and each one is needed.

Findings, in order of impact:

1. **FTS index never built (F-P0-3).** 0 of 2,626 rows are indexed, and nothing calls `optimize()`.
   Unindexed rows are flat-scanned. About 3 in 20 common-token queries crash Lance, and
   `hybrid_search` silently answers those with dense (now counted in `common.HYBRID_FALLBACKS`).
   Building the index on the stored tables takes MRR from 0.177 to 0.482. Phase 1 creates the
   index and calls `optimize()` after writes and in dream.
2. **Stale vectors (F-P0-1).** Every vector written before 2026-08-02 differs from a fresh embedding
   of its own stored text (median cosine 0.89, min 0.68, 400-row sample over all projects). Every
   row from 2026-08-02 on matches exactly (1.000). Ruled out:
   - the endpoint: `/api/embeddings` and `/api/embed` give identical vectors today;
   - truncation and re-scrubbing: short texts and unscrubbed texts are just as far off;
   - a write-path bug: git history has no commits between 2026-05-01 and the cutoff, and the only
     Lance `update()` calls write `superseded_by`, never `text`.

   The installed plugin was 0.5.4 throughout, so the likely cause is an Ollama runtime or model
   change, not yet confirmed. Re-embedding alone takes dense MRR from 0.198 to 0.370. Fix:
   re-embed in the Phase 8 migration (with backup), and store an embedding fingerprint (model,
   Ollama version, probe-vector hash) per project so doctor can detect drift.
3. **Decay re-sort harms ordering (F-P0-2).** The final sort by `decay_score` alone throws away
   relevance order inside the top-k. Recall is unchanged (hit@5 equal on and off), but MRR rises by
   0.21 to 0.33 when the sort is off, on every re-embedded model (synthetic: +0.38). On today's stale
   tables it is neutral (−0.015 stored, +0.009 with FTS), because the relevance order it destroys is
   itself poor. Phase 1 replaces it with relevance × modest multipliers (R1), tuned on this harness.
   The decay path also costs about 30 ms p50 (37 vs 7 ms) for a handful of id lookups; this is noted
   for Phase 5.
4. **Prompt injection never fires with hybrid on (F-P0-4).** The UserPromptSubmit gate reads
   `_distance`, which hybrid results do not carry, so the default 0.8 gate rejects everything
   (inject hit 0.00 on every hybrid variant; dense variants inject 3–73% of the time with no false
   injections). Existing tests run with `hybrid = false` and miss it. Phase 1 fixes it with a
   relevance-score gate tuned on the no-answer questions.
5. **Raw transcript stored as memory (F-P0-5).** Most plugin-project chunks are 2,000-char slices of
   raw JSONL (passthrough distillation after the `--bare` auth failure), not distilled facts. This
   is W2/W3. Phase 8 re-distills them once the CLI path works, and corpus coverage is checked
   before and after.
6. **Meta/Lance mismatch (F-P0-6).** One project has 21 meta rows with no LanceDB row (2,647 meta
   vs 2,626 Lance). Doctor reports it, and the Phase 8 migration reconciles it.

Embedding model choice: snowflake-arctic-embed2 (with its query prefix), qwen3-embedding:0.6b and
bge-m3 lead. The current model, nomic, trails them by about 0.1–0.16 MRR. The CIs overlap at
n=37, so the switch is decided after Phase 1 on a larger question set, and it ships only together
with the re-embed migration.

### Phase 1 — Correctness fixes, re-measure
- R1/R2: one `scripts/retrieval.py` pipeline used by recall, MCP, inject and UI. It fetches a candidate
  pool (`top_k × 5`, min 25), then hybrid RRF, then an optional rerank, then a **final score =
  relevance (RRF/rerank) × modest multipliers** (decay, trust, validity). The multipliers are tuned on
  the eval and can never reorder by recency alone.
- R4: delete the triplicated STDP, RIF and labile helpers; single implementation in `retrieval.py`.
- S1: `scripts/lance_filter.py` — a tiny builder with strict validation (`kind` ∈ enum, ids match
  `^[0-9a-f-]{36}$`, ints coerced). All 38 `where(f…)` sites routed through it. SQLite is already
  parameterised; check every UPDATE.
- S2 / SEC-005: every UPDATE carries `AND project = ?`; MCP pin/unpin/forget scoped to the caller's
  project; test that cross-project ids are rejected.
- R5 / SEC-004: hypothesis filter + trust filter on global recall.
- W1: `distill.render(kind, **vars)` + `distill.call(prompt, model)`; no double rendering. Tests
  assert the LLM receives no `{…}` placeholders.
- W2/W3: all CLI calls go through one `cli.run_claude(prompt, model, timeout)` helper (resolver,
  `cwd=BRAIN_ROOT`, `--bare`, no tools, failure classification).
- W6: align judge prompt and parser on `CONTRADICTS | EXTENDS | UNRELATED | DEFER`; failures return
  `None` (not a verdict); wire `judge_with_project_context`.
- W7, W8, W9, W10, W11, R6 (normalise vectors before L2 gating, or switch gates to cosine).
- **Re-run eval**, record delta vs Phase 0.

### Phase 2 — Provenance and poisoning defence
- Schema: `source` (`user | assistant | tool | web | file | distilled | imported`), `trust` (0–1),
  `taint` (JSON list of sources that fed it).
- Capture parses the transcript tail **by role**: user turns, assistant text, tool_use/tool_result
  (with tool name: `WebFetch`/`WebSearch`/MCP → `web`, Bash/Read → `tool`/`file`). The distiller
  receives tagged segments and emits per-bullet tags (`[user]`, `[claude]`, `[tool]`, `[web]`).
  Chunk trust = min over contributing sources (taint propagates through merges, arcs and
  reconsolidation: a derived memory is never more trusted than its least-trusted input).
- Policy (configurable):
  - `web` and `tool` memories are **never auto-injected** at SessionStart or UserPromptSubmit.
  - They are down-ranked in search (×0.6) and shown with a `[source: web]` label.
  - They never trigger supersession of a `user` memory.
  - Imperative-looking text from low-trust sources is quarantined (`kind=quarantine`) and visible
    only via explicit search or the UI.
- All injected memory is wrapped as data: `<brain-memory source=… trust=… date=…>…</brain-memory>`
  under a one-line factual preamble ("Recalled notes from earlier sessions; reference only").
- `<private>…</private>` spans are dropped at capture (table-stakes parity with claude-mem).
- Eval: poisoning items in the synthetic suite; metric = poisoned items injected (target 0).

### Phase 3 — Temporal validity (Zep-style bi-temporal)
- Schema: `valid_from` (event time; defaults to capture ts), `invalid_at` (nullable), keep `ts` as
  record time, `superseded_by` remains the link.
- The judge on CONTRADICTS sets `old.invalid_at = new.valid_from` (no deletes). EXTENDS adds an edge.
- Retrieval: `as_of` parameter (default now). "Now" excludes invalidated items; `as_of=T` returns
  items valid at T; `include_history=true` returns the chain with dates.
- MCP `search_memory(…, as_of=None, include_history=False)`; injection shows dates.
- Judge moves partly onto the insert path for cheap cases (high-similarity, same kind) via the
  batched session-end distill (Phase 5), so contradictions don't wait for 03:00.
- Eval: knowledge-update and temporal categories.

### Phase 4 — Core memory tier
- **Layered storage (decision D4 = layered):**
  - `~/.claude/brain/core/` is its own git repo, auto-committed on every change (history and diffs;
    you may push it yourself to a private remote). It holds `_global.md` for personal conventions
    across projects, `<repo-name>.md` for project-private memory (the default), and
    `<repo-name>.proposed.md` for dream proposals.
  - The frontmatter of each project file stores the repo path and remote URL, so moves and renames
    re-link.
  - Opt-in shared layer: `<repo>/.claude/brain/CORE.md`, committed with the code. Only items you
    explicitly target at it go there; scrubbed; never from low-trust sources.
- Format: markdown sections `## Decisions`, `## Conventions`, `## Lessons`, `## Pinned`. Each bullet
  carries a date, source and stable id comment `<!-- m:abcd1234 -->` linking it to its DB record
  (provenance, validity, history).
- **The file is the source of truth.** The DB indexes it and re-reads it when the mtime changes.
  Hand edits win, and deleting a line retires the memory.
- Injected in full at SessionStart: project-shared + project-private + global, **≤ 200 lines in
  total**, project lines first. It is never truncated silently; doctor warns at 80 %.
- Writes:
  - `/biss-brain:remember --core [--shared|--global]`, plus MCP `core_add` / `core_remove`.
  - The dream pass only *proposes* (with the target layer). `/biss-brain:core review` accepts or
    rejects proposals.
- Native-import export is opt-in only: `/biss-brain:core export` prints a CLAUDE.md `@import` line
  for you to add yourself (decision: opt-in command).
- Role vs built-in auto memory: auto memory stays off. Core memory is curated and
  provenance-tagged. doctor warns if both are on.

### Phase 5 — Proactive injection, cost and latency
- UserPromptSubmit:
  - Skip trivial prompts (length/command heuristics, `/` commands).
  - Embed with a hard 300 ms budget, falling back to BM25-only when Ollama is slow or down.
  - Candidate pool, then the Phase-1 pipeline, then a **calibrated threshold** (fit on eval for
    precision ≥ 0.7), top-k ≤ 3, ≤ 1,500 tokens.
  - **Session ledger** dedup: `~/.claude/brain/<p>/sessions/<sid>.injected` holds the ids already
    injected or core-memory ids, and they are never re-injected.
  - Trust filter.
  - Default **on**, with the per-project kill switch.
  - Latency is logged to `inject_metrics.jsonl` for doctor.
- Capture/distill cost:
  - Stop just appends a cheap event (use `last_assistant_message`, no transcript parse).
  - Distill once per **segment**, at SessionEnd, PreCompact, idle 10 min or max N events. One CLI
    call per segment produces all bullets + salience + provenance tags as JSON, replacing separate
    salience calls.
  - Reconsolidation merges batched in the same call where possible.
- PreCompact: capture the transcript slice to the queue (≤ 2 s) and return; distill async.
  SessionStart:compact injects the pre-compact summary when ready, else the raw-tail digest.
- Degradation:
  - CLI missing or failing: store the event as `pending_distill`, retried by the flush daemon or
    dream. Never truncate-and-forget.
  - Ollama down: insert with null vector (`pending_embed`), BM25 still works, backfill later.
  - Fallback chain configurable: `claude_code → ollama(qwen2.5:14b) → pending`.

### Phase 6 — Hook scoping and launcher
- hooks.json / .mcp.json / commands: use `${CLAUDE_PLUGIN_ROOT}` only (exec form where supported).
  `_run.sh` keeps a guard that exits 0 if the root is unset.
- Scope:
  - `[scope] exclude = ["~", "~/Downloads", "~/Library", "~/.claude", "/tmp"]` (prefix match;
    `~` exact). Optional `include_only`.
  - Per-project opt-out file `.biss-brain-ignore` (or `.claude/brain.toml` with `enabled=false`).
  - Checked in `_run.sh` with a precomputed exclude list (`~/.claude/brain/scope.cache`), so
    excluded dirs never start Python.
- Project key = git common-dir toplevel (covers `.trees/`, any worktree, subdirectories) with
  realpath fallback (decision D3).

### Phase 7 — Brain mechanisms: ablate, keep or retire
- Run the full ablation matrix (synthetic + real, replay mode) on the Phase-6 build.
- For each mechanism (salience, reconsolidation, STDP, RIF, decay, DMN, dream 1a/1b/2a/2b, backlinks,
  global promotion, reranker), record ΔMRR / Δrecall@5 / latency / LLM-cost, with a verdict:
  **keep (default-on)**, **keep (opt-in)**, or **retire (code stays, default-off, documented why)**.
- Reconsolidation gated HiMem-style: merge only when the retrieved memory was used *and* new
  evidence revises it (not on mere retrieval).
- Results go in `docs/eval/v0.7-ablation.md`; README "Brain mechanisms" table cites them.

### Phase 8 — Migrations, doctor, docs, release
- **Release gate — the fresh start must run before 0.7.0 ships.** It runs once the old data is
  no longer needed:
  1. Phases 2–7 are evaluated. Each eval needs the old corpus, which lives in the frozen snapshots
     `~/.claude/brain-eval/snapshots/v0.6-*` (made 2026-10-26), not in the live brain.
  2. The larger eval suite and the model-switch decision (F-P1-1) are settled.
  3. `fresh_start.py --apply` runs with the user's confirmation. It moves the live brain to
     `~/.claude/brain-archive/` and never deletes it. A later suite is written against the new store.
  Until then, the progress log carries this as an open item.
- **D8 (fresh start) supersedes the data migration below**: ship `scripts/fresh_start.py`
  (dry-run default; `--apply` moves `~/.claude/brain` to `~/.claude/brain-archive/brain-<ts>/`
  and creates the v0.7 layout with the chosen embed model and fingerprint). Steps 3 and 4 below
  are dropped; the schema code still has to work on an empty store and refuse to open a store with
  a mismatched embed fingerprint.
- `scripts/migrate_v07.py` (dry-run default, `--apply`), kept only for the schema step:
  1. **Mandatory backup**: `tar` of `~/.claude/brain` into `~/.claude/brain-backups/brain-<ts>.tar.gz`.
     Aborts on failure. Never deletes the original.
  2. Additive schema: provenance, temporal, `distill_state`, `schema_version`.
  3. Mark the 2,000-char passthrough chunks `source=imported, distill_state=raw, trust=0.5`.
  4. Optional steps per §6: re-distill raw chunks, re-embed, fold worktrees/subdirs, exclude junk
     projects (moved to `~/.claude/brain/_excluded/`, not deleted).
- `run_v07_migrations.sh` modelled on the v0.6.1 runner (backup → plan → confirm → apply).
- doctor checks:
  - resolver path plus a live `claude -p` ping (optional flag)
  - embed model pulled and table dim = config dim
  - schema version and FTS index present
  - launchd job loaded/healthy, with the last dream result
  - recent CLI failures, pending_distill/pending_embed backlog
  - inject latency p95
  - scope config, core memory size (≤ 200 lines), auto-memory overlap
- Docs: README rewrite (accurate stack, mechanisms table with evidence), `docs/architecture/00-overview.md`
  v0.7 section, CHANGELOG, `config.toml.example`.
- Version: plugin.json + pyproject → **0.7.0** (minor: new features; migrations are additive and
  backwards-compatible).
