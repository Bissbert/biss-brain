# v0.7 mechanism ablation (Phase 7)

Run 2026-10-26 on the Phase 6 build (`73bddb9`, plus the 7.1 reconsolidation gate).

## Rule

From `docs/plans/v0.7-upgrade.md` §4:

> Keep if ΔMRR ≥ +0.01 (bootstrap 95 % CI excludes 0), or ΔMRR within ±0.01 at ≤ 5 ms/query and
> no LLM cost; else default-off.

"Default-off" retires a mechanism without deleting it: the code stays, a config key turns it back on.

## Method

- **Suites:**
  - **Real:** `~/.claude/brain-eval/questions.jsonl`, with 37 answerable and 12 no-answer questions, run against the frozen snapshot `v0.6-plugins-fts`.
  - **Synthetic:** the built-in fixture, with 26 answerable and 11 no-answer questions.
  - Both suites use `nomic-embed-text` (768-dim) through Ollama, k = 5.
- **Read path:** `scripts/eval/run_eval.py --variants prod,dense,no_decay,summary_first,no_trust` on the frozen store. ΔMRR is a paired bootstrap against `prod`.
- **Stateful effects:** `scripts/eval/ablate.py` replays the suite on private copies of the snapshot. Each answerable question is read once with the post-retrieval effects on (retrieval counts, STDP edge bumps, RIF), and dream stage 1c runs where an arm asks for it. Every arm is then measured with the production ranking.
  - The replay reads the very questions it then scores, so the usage numbers are an in-sample upper bound, which favours the mechanisms.
  - STDP's co-retrieval queue may land under the temporary eval root rather than the arm copy. That doesn't matter, since STDP has no ranking path (see below).
- **Run files** are kept out of the repo, under `~/.claude/brain-eval/runs/`:
  - `phase7_read.json` and `phase7_read_synth.json` (read-path variants);
  - `phase7_replay.json` and `phase7_replay_synth.json` (replay arms).

### Snapshot limits

The v0.6 snapshot predates provenance and has never been through dream stage 2. It has no `taint` column, and no `arc` or `daily_summary` rows.

On the real suite, `no_trust` and `summary_first` therefore equal `prod` by construction, with CI [0, 0]. Their verdicts rest on the synthetic suite.

## Results

### Read path (frozen store)

| Variant | Real MRR | Real ΔMRR [95 % CI] | Synthetic MRR | Synthetic ΔMRR [95 % CI] | Retrieve p95 (real) |
|---|---|---|---|---|---|
| prod (hybrid, decay, trust) | 0.764 | — | 0.668 | — | 89 ms |
| dense (no BM25) | 0.693 | −0.071 [−0.171, +0.031] | 0.808 | +0.140 [−0.003, +0.302] | 52 ms |
| no_decay | 0.764 | 0.000 [0, 0] | 0.710 | +0.042 [0.000, +0.103] | 88 ms |
| summary_first | 0.764 | 0.000 (structural) | 0.543 | −0.125 [−0.231, −0.010] | 89 ms |
| no_trust | 0.764 | 0.000 (structural) | 0.642 | −0.026 [−0.077, 0.000] | 86 ms |

- **Poison:** with `no_trust`, 11 of the synthetic suite's queries get a poisoned (tool or web) row at top-1. With `prod`, none do.
- **Synthetic decay is not evidence against decay.** The fixture's decay scores date from build time. After one dream 1c pass (`frozen_dream`), synthetic `prod` scores 0.710 / hit@5 0.885, exactly what `no_decay` scores. The nightly recompute flattens them, so the synthetic `no_decay` gain shows a stale fixture, not a decay problem.

### Stateful effects (replay)

|---|---|---|
| frozen | 0.764 | 0.668 |

The table below is the cost of `effects.apply_post_retrieval` per read, on the real suite. The synthetic suite gives the same picture.

| Effects on | p50 | p95 |
|---|---|---|
| all | 170 ms | 219 ms |
| without RIF | 0.4 ms | 0.5 ms |
| without STDP | 188 ms | 209 ms |
| neither | 0.3 ms | 0.5 ms |

RIF accounts for the whole cost. It runs about 11 ANN queries per hit inline in the read path.

## Verdicts

| Mechanism | Evidence | Verdict |
|---|---|---|
| **Hybrid retrieval (BM25 + dense)** | Real −0.071 without BM25 (CI crosses 0), synthetic +0.140 without BM25 (CI crosses 0). Costs about 37 ms p95. | **Keep (default-on), outside the rule.** It does not pass the rule as written: neither CI excludes 0 and it costs more than 5 ms. It stays on because BM25 is the fallback when the embedder misses its 300 ms budget (Phase 5) and the only search over rows without a vector. Was not on the Phase 7 list. |
| **Decay in ranking** (`decay_weight` 0.05) | Real 0.000. Synthetic +0.042 for `no_decay` is a fixture artefact (see above). No measurable cost, no LLM. | **Keep (default-on)** under the ±0.01 clause. |
| **Usage boost in nightly decay** (`1 + 0.2 × retrieval_count`) | −0.018 real and −0.019 synthetic, upper CI 0.000 on both. No gain on either suite. | **Retire:** `hygiene.decay_usage_boost = 0.0`. Set it to 0.2 to restore the v0.6 behaviour. |
| **RIF** (retrieval-induced forgetting) | Real **−0.105**, with the CI excluding 0; about 170 ms per read; erased each night anyway, because dream 1c rewrites `decay_score` from scratch. | **Retire:** `rif.enabled = false`. |
| **Provenance rank multiplier** (tool/web × 0.6) | Synthetic only: −0.026 without it, and poisoned top-1 rises from 0 to 11 queries. Real suite: structural zero (the snapshot has no tool/web rows). No cost. | **Keep (default-on), outside the rule.** The ΔMRR clause is met only on the synthetic suite. It stays on as a safety control against poisoned tool/web content. Was not on the Phase 7 list. |
| **Summary first** (`prefer_summaries_in_recall`) | Synthetic −0.125, with the CI excluding 0. Real suite: structural zero. | **Keep opt-in (default-off, unchanged).** |
| **Reconsolidation** | Not measured: a write-time LLM merge, which the frozen suites cannot score. 7.1 gates it HiMem-style: only memories that were used inside the labile window, and only when the new text adds ≥ 20 % new content terms. A restatement is folded in without an LLM call. | **Not measured; default kept (on, gated). User decision.** The gate saves one CLI call per restatement. |
| **STDP edges** | Feed only `related_to` / `fetch_related`, never ranking, so ΔMRR is 0 by construction. Cost under 0.2 ms per read. | **Keep (default-on).** It is cheap and serves the MCP graph tools. |
| **Backlinks (dream 1a), DMN** | Same as STDP: graph tools only, structural zero for ranking. No LLM. | **Keep (default-on).** |
| **Salience** | Stored at distill time, but read by no ranking path (only `migrate_recover_orphans` reads it). Free: the same distill call produces it. | **Keep stored, not used.** Wiring it into ranking needs a suite with salience labels. |
| **Conflict sweep (1b)** | Not measured here: it changes which rows are superseded, which the frozen suite cannot score. Up to one Haiku call per new chunk. | **Not measured; default kept. User decision.** |
| **Session arcs (2a), daily summary (2b)** | Not measurable on this snapshot (no arc rows). 2a costs one Haiku call per session; 2b is opt-in. | **Not measured; defaults kept (2a on, 2b off). User decision.** |
| **Global promotion** | Not measured: the suites are per project. No LLM. | **Not measured; default kept. User decision.** |
| **Cross-encoder rerank** | Not run: FlagEmbedding is not installed, and the fallback would download a model. Off by default since Phase 1. | **Keep opt-in (default-off, unchanged).** |

## Behaviour changes in v0.7

- `rif.enabled` now defaults to `false`. It was `true`.
- `hygiene.decay_usage_boost` now defaults to `0.0`. It was 0.2, hard-coded.
- Reconsolidation merges only when the new text revises the memory (`reconsolidation.revise_min_novelty`, 0.2).
