## Must-Fix Findings

### SEC-001 — dmn.py `_refresh_recent_backlinks` NameError on `_parse_related_ids`

- **Severity:** High
- **Category:** Quality / Runtime Correctness
- **Location:** `scripts/dmn.py:423`
- **Description:** F-003 imported `_add_typed_edge` from backlinks but omitted `parse_related_ids`. The DMN backlink refresh silently fails on every tick where chunks pass the L2 gate. The exception is swallowed by the per-project `except Exception: pass` at `dmn.py:521`, masked further by `tests/test_dmn.py:401–403`.
- **Evidence:**
  - `scripts/dmn.py:47` — import only `_add_typed_edge`
  - `scripts/dmn.py:423` — `_parse_related_ids(row[0])` without import
  - `tests/test_dmn.py:401–403` — exception swallowed silently
- **Impact:** DMN backlink refresh is a no-op; STDP edges still drain but related_ids stays stale.
- **Recommendation:** Replace `dmn.py:47` with `from backlinks import _add_typed_edge, parse_related_ids as _parse_related_ids`. Update `tests/test_dmn.py:401–403` to assert success.
- **Status:** open

### SEC-002 — `_recent_decisions` lacks hypothesis quarantine filter (residual F-002)

- **Severity:** Medium
- **Category:** Security (invariant gap)
- **Location:** `scripts/inject_context.py:101`
- **Description:** F-002 added `kind != 'hypothesis'` to the LanceDB WHERE paths but missed the SQLite `_recent_decisions` query used by the `session_start` hook. Hypothesis chunks (when `rem.enabled = True`) would surface into session_start context.
- **Evidence:**
  - `scripts/inject_context.py:96–136` — `_recent_decisions` query has no hypothesis filter
  - `scripts/inject_context.py:337–338` — `session_start` calls `_recent_decisions`
  - `tests/test_hypothesis_quarantine.py` — does not cover session_start path
- **Impact:** §6 Invariant 2 violated for the session_start injection path. Latent (default-off `rem.enabled`).
- **Recommendation:** Add `AND kind != 'hypothesis'` to the `_recent_decisions` SQL. Add a session_start test to `tests/test_hypothesis_quarantine.py`.
- **Status:** open

### SEC-003 — `_write_cross_link` is dead code in production

- **Severity:** Medium
- **Category:** Security (invariant partially implemented)
- **Location:** `scripts/recall.py:340–386`
- **Description:** The R4 invariant requires cross-project hits to write to `cross_links`. The writer is correctly defined and tested but never invoked from production. `_recall_global` annotates results but does not call `_write_cross_link`. The `cross_links` column is always empty in production DBs.
- **Evidence:**
  - `scripts/recall.py:340` — definition only; no production call sites
  - `scripts/mcp/server.py:291` — `_recall_global` called; no `_write_cross_link` follow-up
  - `tests/test_global.py:442,462` — only test invocations
- **Impact:** R4 half-implemented. Downstream code reading `cross_links` sees empty arrays.
- **Recommendation:** In `recall.py` and `mcp/server.py` cross-project recall paths, after `_recall_global` returns hits, call `_write_cross_link(meta, local_chunk_id, global_id, weight=cosine)` for each qualifying hit. Requires identifying which local chunk surfaced the cross-project result (or writing per-query).
- **Status:** open

### SEC-005 — `flush.py:517` and `forget.py:34` lack SQL-level project guard on `superseded_by` UPDATE

- **Severity:** Low
- **Category:** Defence-in-depth
- **Location:** `scripts/flush.py:517`, `scripts/forget.py:34`
- **Description:** Both writes are structurally scoped via per-project `open_meta(cwd)`, so cross-project supersession is currently impossible. The §6 invariant text requires SQL-level same-project guards as the strongest form.
- **Recommendation:** Add `AND project = ?` to both UPDATE WHERE clauses to bring all three sites to SQL-level compliance with §6.1.
- **Status:** open

## Detailed Analysis

### R1 — Hash Dedup Collapse Across Projects — PASS

`flush.py:580` and `remember.py:178` issue `SELECT id FROM chunks WHERE content_hash = ?` with no explicit `AND project = ?`. Both call `open_meta(cwd)` which resolves to a per-project SQLite file (`BRAIN_ROOT / project_key(cwd) / meta.sqlite`). No shared cross-project DB exists in v0.5. Dedup operates only within the caller's project.

### R2 — Silent Cross-Project Supersession — PARTIAL PASS

Three sites write `superseded_by`:

| Site | WHERE | Project guard |
|---|---|---|
| `dream.py:392` | `WHERE id = ? AND project = ?` | YES (F-004) |
| `flush.py:517` | `WHERE id = ?` | Structural only |
| `forget.py:34` | `WHERE id = ?` | Structural only |

The `judge_with_project_context` R2 structural rewrite is unconditional (`judge.py:211–228`) but the function has zero production call sites. Production paths use `judge_conflict` directly, which only sees same-project candidates because of within-project LanceDB filtering.

### R3 — `retrieval_count` Bias — PASS

`_bump_retrieval_count_local` uses `WHERE project = ? AND id IN (...)`. Cross-project results from `_recall_global` are constructed AFTER `meta.commit()` and `meta.close()` in both `recall.py:494–516` and `mcp/server.py:264–291`. `inject_context.py` does not call `_recall_global`.

### R4 — Cross-Project Backlink False Positives — PASS (write isolation); SEC-003 (dead code)

`_write_cross_link` writes exclusively to `cross_links`. Cosine gate (≥ 0.85) enforced in `_recall_global:326–327`. But the writer is never called in production (SEC-003).

### §6 Codebase-Grep Invariants

1. **§6.1 Cross-project supersession forbidden** — PARTIAL (see R2)
2. **§6.2 Hypotheses quarantined** — PARTIAL (SEC-002)
3. **§6.3 No local count bump from cross-project** — PASS
4. **§6.4 cross_links never in related_ids** — PASS
5. **§6.5 `_global` admission gated** — PASS (with SEC-004 latent gap)
6. **§6.6 Default-off flags** — PASS

### Race-Condition Audit (DMN vs NREM-2 drainer)

Both `dmn.py:299` and `dream.py:1074` use `BEGIN IMMEDIATE`. Both mark drained per-pair (`WHERE project = ? AND chunk_a = ? AND chunk_b = ? AND drained = 0`). The first drainer to acquire the IMMEDIATE lock wins; the second sees no above-threshold rows for that pair. F-003 correctly fixed the over-broad mark-drained semantics.

### `_two_phase_promote` SQL binding count — PASS

15-column INSERT with 8 `?` placeholders + 7 literals; tuple at `dream.py:958–965` supplies exactly 8 values. Binding count correct.

### SEC-006 — `_open_meta_direct` does not bootstrap `chunks` table or apply v0.5 migration

- **Severity:** High (blocks first cross-project promotion when flag flipped on)
- **Category:** Schema bootstrap / runtime correctness
- **Location:** `scripts/dream.py:_open_meta_direct` (around line 133)
- **Description:** `_ensure_global_project` calls `_open_meta_direct` to bootstrap the meta.sqlite for the `_global` project. The helper only ALTER-TABLE'd v0.4 columns and assumed the `chunks` table already existed. On a fresh `_global` directory it failed with `no such table: chunks`. After bootstrapping `chunks`, it then failed again because the v0.5 columns (`cross_eligible`, `cross_links`, `salience`, …) were never added.
- **Trigger:** First-ever cross-project promotion (only when `cross_project.enabled = true`, default-off). Why CI tests didn't catch: tests construct meta DBs via `common.open_meta` which does the full migration; only the `_global` bootstrap path goes through `_open_meta_direct`.
- **Fix:** Added `CREATE TABLE IF NOT EXISTS chunks` + the seven v0.5 ALTER-TABLE statements + `edge_bumps`/`dream_state` table creates + `idx_chunks_labile` index to `_open_meta_direct`. Mirrors `common._ensure_schema` exactly.
- **Status:** **Resolved** in commit (see Resolution-2 below).
